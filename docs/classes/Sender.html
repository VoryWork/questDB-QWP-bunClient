    Class Sender

    The QuestDB client's API provides methods to connect to the database, ingest data, and close the connection.

    The client uses the QuestDB Wire Protocol (QWP) over a WebSocket connection.

    • ws: Plain WebSocket connection to the QuestDB wire protocol endpoint (/write/v4).
    • wss: TLS-secured WebSocket connection.

    The client supports Basic username/password and Bearer token authentication, passed in the Authorization header during the WebSocket upgrade handshake. Note that authentication is enabled by default in QuestDB Enterprise only.

    The client buffers rows in a columnar format and sends them to the server as binary QWP messages. Auto-flushing can be controlled via the configuration options.

    It is recommended that the Sender is created by using one of the static factory methods, Sender.fromConfig(configString, extraOptions) or Sender.fromEnv(extraOptions).

    Configuration Examples:

    • ws::addr=localhost:9000
    • wss::addr=localhost:9000;username=admin;password=secret
    • ws::addr=localhost:9000;auto_flush=off;auto_flush_rows=1000

    Extra options can be provided to the Sender in the extraOptions configuration object. A custom logging function can be passed in this object.

    flush

    • flush(): Promise<boolean>

      Flushes all buffered rows by sending them to the server in a single QWP message, waiting for the server's acknowledgement.

      Flushes are serialized: a flush that arrives while another one is in flight waits for it to finish, so rows buffered by an in-flight flush are never collected twice.

      Returns Promise<boolean>

      Promise resolving to true if data was sent, false if the buffer was empty
