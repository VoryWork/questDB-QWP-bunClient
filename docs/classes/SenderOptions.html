    Class SenderOptions

    Sender configuration options.
    Properties of the object are initialized through a configuration string.
    The configuration string has the following format: protocol::key=value;key=value...
    The keys are case-sensitive, the trailing semicolon is optional.
    The values are validated and an error is thrown if the format is invalid.

    Connection and protocol options

    • protocol: enum, accepted values: ws, wss - The protocol used to communicate with the server.
      Both protocols use the QuestDB Wire Protocol (QWP) over a WebSocket connection.
      When wss is used, the connection is secured with TLS encryption.
    • protocol_version: enum, accepted values: auto, 1 - The protocol version used for data serialization.
      QWP currently supports a single version, so this option always resolves to 1.
    • addr: string - Hostname and port, separated by colon. This key is mandatory, but the port part is optional.
      If no port is specified, a default will be used.
      The port defaults to 9000 for both ws and wss protocols.

      Examples: ws::addr=localhost:9000, wss::addr=localhost:9000, ws::addr=localhost

    Authentication options
    • username: string - Used for Basic authentication, requires the password option. The credentials are sent in the Authorization: Basic ... header during the WebSocket upgrade handshake.
    • password: string - Password for Basic authentication, should be accompanied by the username option.
    • token: string - Bearer token, sent in the Authorization: Bearer ... header during the WebSocket upgrade handshake. Note that token-based authentication is supported by QuestDB Enterprise only.

    TLS options
    • tls_verify: enum, accepted values: on, unsafe_off - When the wss protocol is selected, TLS encryption is used.
      By default, the Sender will verify the server's certificate. Note: the Bun runtime does not currently support custom CA certificates or disabling certificate verification for the client WebSocket API. These options are accepted for configuration compatibility but are not applied by the transport.
    • tls_ca: string - Path to a file containing the root CA's certificate in PEM format.
      Accepted for configuration compatibility; not applied by the Bun WebSocket transport.

    Auto flush options
    • auto_flush: enum, accepted values: on, off - The Sender automatically flushes the buffer by default. This can be switched off by setting this option to off.
      When disabled, the flush() method of the Sender has to be called explicitly to make sure data is sent to the server.
      Manual buffer flushing can be useful, especially when we want to control transaction boundaries.
      Each flush results in a single QWP message, which becomes a single transaction on the server side.
      The transaction either succeeds, and all rows sent in the request are inserted; or it fails, and none of the rows make it into the database.
    • auto_flush_rows: integer - The number of rows that will trigger a flush. When set to 0, row-based flushing is disabled.
      The Sender will default this parameter to 1000 rows.
    • auto_flush_interval: integer - The number of milliseconds that will trigger a flush, default value is 1000. When set to 0, interval-based flushing is disabled.
      Note that the setting is checked only when a new row is added to the buffer. There is no timer registered to flush the buffer automatically.

    Buffer sizing options
    • init_buf_size: integer - Initial buffer size, defaults to 64 KiB in the Sender.
    • max_buf_size: integer - Maximum buffer size, defaults to 100 MiB in the Sender.
      If the buffer would need to be extended beyond the maximum size, an error is thrown.

    Request specific options
    • request_timeout: integer - The time in milliseconds to wait for the WebSocket connection and for each server acknowledgement, set to 10 seconds by default.
    • request_min_throughput: integer - Accepted for configuration compatibility; not used by the WebSocket transport.
    • retry_timeout: integer - Accepted for configuration compatibility; the WebSocket transport does not retry.

    Other options
    • max_name_len: integer - The maximum length of a table or column name, the Sender defaults this parameter to 127.
      Recommended to use the same setting as the server, which also uses 127 by default.
